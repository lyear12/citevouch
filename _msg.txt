Ship the archive with every file its own suite reads

`MANIFEST.in` said `graft tests` and the published source archive shipped
`tests/` without the files those tests open: `tools/`, `.pre-commit-hooks.yaml`,
`action.yml`, `.github/`, `docs/img/` and `demo/papers/`. Unpacking the released
`citevouch-0.16.1.tar.gz` and running `PYTHONPATH=src python -m pytest` gave 56
failures and 3 errors. The demo was the worst of it: without its papers,
`demo/manuscript.md` reports five `source-missing` findings - every claim red,
for a reason that is about the archive and not about the manuscript.

The fix is rules, not a longer list. `MANIFEST.in` now grafts `tools/` and
`.github/`, includes `action.yml` and `.pre-commit-hooks.yaml`, carries
`docs/img/` and ships the demo whole. `tests/test_sdist_contents.py` reads the
suite with `ast` and collects every path it names - including paths built as
`ROOT / "tools" / "next_version.py"`, which is how tests name most files and
which a scan for slashes in string constants misses (it found 14 of 44) - then
fails if the archive lacks one. Restoring the old manifest and rebuilding turns
three of those tests red.

Two tests counted `git ls-files`, which has no meaning outside a checkout, so
they now skip themselves there and say why. `test.yml` gained an `sdist` job
that unpacks the archive, runs its suite, and requires the skip count to be
exactly two: a skip is how those tests stay honest, and also how a suite goes
quiet.

Run: PYTHONPATH=src python -m pytest (508 passed); python -m ruff check .;
sh tools/format_check.sh (72 files); python -m build --sdist --no-isolation;
unpacked that archive and ran its own suite (501 passed, 2 skipped);
PYTHONPATH=src python -m citevouch verify demo/manuscript.md --root demo
(5 claims - 4 verified, 0 moved, 1 missing, exit 1, deliberate);
check_repo_rules --range HEAD~1..HEAD --passed 508 --formatted 72.

Not tried: the new `sdist` job itself, which only runs on a GitHub runner; the
PyPI upload, which still has no trusted publisher registered; a build from the
archive on a machine without `pypdf` already installed.

Broken by hand: none.
